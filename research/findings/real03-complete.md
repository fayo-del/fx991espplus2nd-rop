## How the game works (per pass, all in-chain)
KEYSCAN 0x4D0E → r0=presence, r2=KID (7F=Right/Up, BF=Left/Down, FF=none) → load POS from
RAM 0x8BBD (`0x16E0C L R0,[ER0]`) → POS' = POS−KID (`0x4AA8 SUB R0,R2`; none → +1 drift) →
store POS' (`0x10470C ST R0,[ER14]`) → if POS' out of band → game-over branch → park; else
draw the 12-byte cell at dst = 0xF8|POS' via memcpy12 0x35BE → pivot 0x75DE re-syncs SP →
next pass (unbounded). Observed POS trajectory in the run: 30 → 79 → 83 → 8D → 97 (drift,
no key) then wrap into the game-over band → POS=01 at park.

## Limits (honest)
- 3 key states in-loop (KID 7F/BF/FF — no 4-way); POS wraps mod 256 in the top 16 LCD rows.
- The zero-free ban applies only to the typed payload; chain-computed stores CAN write 0x00
  (MB05), but real03 keeps the simpler drift+park rules that fit the 100-byte payload.
- Park 0x4EF2 is terminal in-emulator ([HW-unknown] whether any key resumes it on hardware).
- In-emulator the pre-trigger payload equip at 0x8154 is the documented stand-in for the
  hand flash-walk delivery; the trigger (AC,◀,EXE) and all player arrows are pure PressKey.
